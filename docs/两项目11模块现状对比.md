## 总结

### framework 领先的（4项）
1. **文件管理** — 完整 PLY/STL/OBJ/PCD 导入导出 + 进度框
2. **编辑** — 有套索/删除/撤销基础功能
3. **标定UI/3D显示** — CalibDialog + CalibDisplay 更完整
4. **应用可用性** — 有可运行的 GUI（MainWindow + OSGWidget）

### K2 领先的（4项）
1. **渲染** — CUDA-GL 零拷贝实时渲染（vs OSG CPU展点）
2. **算子完整性** — 多 optical_flow_fuse + 完整温度补偿链 + ctest覆盖
3. **模块化** — 模块目录都有代码、命名正确
4. **并行流水线设计** — 文档设计完整（P-core Broker/GpuService/RingBuffer/E-core编排）

### 共同短板（5项）
后处理编排、会话管理逻辑、扫描并行流水线、可观测性、安装部署——**两个项目都未实现**。

### 一句话结论

**framework = "能跑的应用"**（UI/IO/渲染/编辑在 app 里可运行，但模块目录空、算子不全）。
**K2 = "完整的架构"**（模块化好、算子全、CUDA-GL渲染、并行设计完整，但缺可用的业务代码）。
**两者互补**：framework 缺 K2 的算子+模块化+CUDA渲染，K2 缺 framework 的可用业务代码。
