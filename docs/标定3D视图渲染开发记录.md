# 标定 3D 视图扫描仪模型渲染开发记录

## 问题描述

标定场景中，3D 扫描仪模型（`JEAMMSCAN.stl`）显示存在三个问题：
1. **透明/看穿**：能看到模型内部
2. **翻转**：旋转视角到 180° 时，模型明暗反转，看着像"翻过来"
3. **镜头朝向错误**：初始视角下镜头朝向用户（应朝屏幕里）

## 排查过程

### 第一步：隔离变量（从干净基线逐项增加）

以 HEAD 原始版本（粗糙平面显示、关光照、半透明）为基线，确认：
- **基线状态**：不翻转、镜头方向正确（但无立体感）

然后**一次只加一项**，每加一项确认翻转与否：

| 步骤 | 改动 | 结果 |
|------|------|------|
| 基线 | 无光照（平面色） | ✓ 不翻转，方向正确 |
| 第1项 | 叉积法线 + GL_LIGHTING + Material | ✗ 翻转 |
| 第2项 | GL_BLEND OFF（不透明） | ✗ 仍翻转 |
| 第3项 | twoSided（双面光照） | ✗ 仍翻转 |
| 第4项 | CULL_FACE（剔除内表面） | ✗ 仍翻转 |

**结论**：光照（明暗着色）本身触发了翻转。

### 第二步：用简单模型排除渲染 vs 模型问题

生成**金字塔模型**（简单、凸面、单组件、CCW-out），用同样的渲染设置测试：
- **金字塔**：不透明 ✓、不翻转 ✓、渲染正常 ✓

**结论**：渲染设置没问题，是**扫描仪 STL 模型本身的问题**。

### 第三步：分析扫描仪模型

对 `JEAMMSCAN.stl` 做几何分析：

| 检查项 | 结果 |
|--------|------|
| 三角面数 | 86678 |
| 边界边（0.1mm 精度） | 226（浮点噪声，实际闭合） |
| 边界边（1mm 精度） | 0（**完全闭合**） |
| 有符号体积 | 正（CCW-out） |
| 最远面绕序测试 | 197/200 朝外（CCW-out 确认） |
| **连通组件数** | **6 个**（主体 65066 面 + 5 个小组件） |

**根因发现**：模型有 **6 个独立组件**，5 个小组件嵌套在主体内部/表面，导致：
- **z-fighting**（嵌套组件的面深度冲突）→ 看穿/透明
- **光照错乱**（嵌套面的法线干扰着色）→ 翻转错觉
- **镜头方向干扰**（小组件的面遮挡/干扰判断）

### 第四步：清理模型

提取**最大组件**（主体外壳，65066 面），去掉 5 个嵌套小组件（21612 面）：
- 生成 `JEAMMSCAN_clean.stl`
- 验证：单壳、闭合（0 边界边）、CCW-out
- **清理后初始镜头方向正确**

## 最终方案

### 模型
- 使用清理后的单壳模型 `JEAMMSCAN_clean.stl`（65066 面）
- 去掉嵌套组件，消除 z-fighting 和透明

### 渲染
- **法线**：叉积重算 `(p1-p0)^(p2-p0)`（STL 自带法线为脏数据）
- **光照**：GL_LIGHTING ON + GL_LIGHT0（viewer 头灯）
- **双面光照**：twoSided = true（背面用反转法线着色）
- **材质**：浅灰（0.75）+ specular 0.3 + shininess 100
- **不透明**：GL_BLEND OFF + OPAQUE_BIN（恢复深度写入）
- **不剔除**：CULL_FACE OFF（单壳模型不需要）

### 相机
- 锁定视角（`setCameraManipulator(nullptr)` + 固定 viewMatrix）
- 禁止旋转和缩放（标定阶段为固定参考视角）

## 关键经验

1. **模型数据是第一嫌疑**：渲染问题要先排除模型本身的几何问题（多组件、嵌套、z-fighting），再查渲染代码。
2. **用简单模型做对照**：遇到渲染问题时，先用已知正确的简单模型（如金字塔）测试，快速定位是模型问题还是代码问题。
3. **一次只改一项**：调试时严格隔离变量，每次只加一个改动，确认效果后再加下一个。
4. **半透明（GL_BLEND ON）会关深度写入**：导致背面穿透显示，与光照叠加会产生严重视觉错乱。标定场景应使用不透明渲染。
5. **凹凸曲面的空心面具错觉（hollow-face illusion）**：光照着色在凹凸模型上转 180° 时，大脑会误判朝向。凸面模型（如金字塔）不触发。标定用固定视角可避免。
6. **STL 自带法线不可信**：扫描导出的 STL 法线常为脏数据（未归一化、超大值），应叉积重算。

## 涉及文件

| 文件 | 改动 |
|------|------|
| `app/CalibDisplay.cpp` | `loadStlManual`：叉积法线 + 光照 + twoSided + Material；`createPoseModel`：不透明（GL_BLEND OFF） |
| `app/MainWindow.cpp` | STL 路径改为 `JEAMMSCAN_clean.stl`；锁定相机视角 |
| `build/JEAMMSCAN_clean.stl` | 清理后的单壳模型（本地文件，不入库） |

# 标定视图姿态偏差彩条开发记录

## 需求

标定和扫描过程中，需要在显示窗口上指示**扫描仪当前姿态和目标姿态的偏差**：
- **左右**偏差：横排彩条，放在显示窗口上侧
- **前后**偏差：竖排彩条，放在显示窗口右侧
- 风格和已有的"远近"滑动条（ArrowSlider）完全一致
- 标定和扫描时显示，后处理时可隐藏

## 开发过程

### 第一阶段：Qt PoseBar 控件（已废弃）

最初创建了自定义 Qt 控件 `PoseBar`，用 QPainter 绘制标签 + 数值 + 5 段绿→红彩条。

**问题**：
- 样式和远近滑动条不一致（远近是 ArrowSlider + 渐变槽 + 箭头手柄，PoseBar 是分段色块）
- 横/竖方向切换、背景颜色、段尺寸反复调整
- 用户反馈"和远近不一样"

**教训**：用户说"和远近一样"时，应该直接复制远近的实现（ArrowSlider），而不是自己设计一套新的控件。

### 第二阶段：改用 ArrowSlider（最终方案）

参考 `create3DViewArea()` 中远近滑动条的实现，直接用 `ArrowSlider`：

**远近的原实现**（`create3DViewArea`）：
```cpp
ArrowSlider *rangeSlider = new ArrowSlider(Qt::Vertical);
rangeSlider->setFixedWidth(48);
rangeSlider->setGroovePixmap(renderSvg("div.color-gradient-bar.svg", 24, 800));
// 蓝色"远"在顶部，红色"近"在底部
```

**需要修改 ArrowSlider**：原 `paintEvent` 只支持竖排，需要增加横排支持。

#### ArrowSlider paintEvent 改造

原代码（只支持竖排）：
- 渐变槽：`scaled(24, height()-20)` 竖向
- 箭头：指向左

新增横排分支：
- 渐变槽：把 SVG 旋转 90° → `scaled(width()-20, 24)` 横向
- 圆头裁剪：`QPainterPath::addRoundedRect`（半径=高度/2）
- 箭头：指向下

#### 布局结构

```
view3DArea (QVBoxLayout)
├── 左右容器 (固定高60px)          ← insertWidget(0) 插入最前
│   ├── stretch(1)                 ← 左侧10%空白
│   ├── QLabel "左"(蓝)
│   ├── ArrowSlider(水平, stretch=8) ← 80%宽度
│   ├── QLabel "右"(红)
│   └── stretch(1)                 ← 右侧10%空白
└── viewContainer (QHBoxLayout)
    ├── 远近滑动条(原有)
    ├── m_3dView (3D视图)
    ├── CalibBoard2D (标定板)
    └── 前后容器 (QVBoxLayout)
        ├── QLabel "前"(蓝)
        ├── ArrowSlider(垂直, 固定宽48px)
        └── QLabel "后"(红)
```

## 关键决策

| 决策点 | 选择 | 原因 |
|--------|------|------|
| 控件类型 | ArrowSlider（不是 PoseBar） | 和远近完全一致 |
| 左右方向 | 水平 ArrowSlider | 横排铺在窗口上侧 |
| 前后方向 | 垂直 ArrowSlider | 竖排放窗口右侧 |
| 渐变方向 | 旋转 SVG 90° | 原 SVG 是竖向渐变，横排需要横向 |
| 两端形状 | 圆头（addRoundedRect） | 用户要求 |
| 左右长度 | 80%（两侧各 10% stretch） | 用户要求缩短 |
| 背景色 | 浅灰(240,240,240) | 和远近区域一致 |

## 涉及文件

| 文件 | 改动 |
|------|------|
| `app/MainWindow.cpp` | `ArrowSlider::paintEvent`：增加水平方向支持（旋转渐变+圆头+向下箭头）；`onCalibDeviceClicked`：创建左右(水平)和前后(垂直)ArrowSlider |
| `app/CalibDisplay.h` | 移除 PoseBar 类声明 |
| `app/CalibDisplay.cpp` | 移除 PoseBar 实现 |

# 模型不透明显示 + 标定/扫描视图切换开发记录

## 问题

1. **模型透明/能看到内部**：开启光照后模型半透明，能看穿到内表面
2. **扫描类按钮不切换视图**：点标点扫描/面片扫描/点云扫描时，3D 视图仍停留在标定界面
3. **彩条只在标定时显示**：左右、前后彩条在扫描时应隐藏，第二次进入标定时应重新显示

## 根因分析

### 模型透明问题

通过**隔离变量法**（从干净基线逐项增加）定位：

| 设置（出问题时） | 值 | 后果 |
|-----------------|-----|------|
| `GL_BLEND` | **ON** | 半透明 |
| alpha | **0.85** | 能看穿到内表面 |
| `RenderingHint` | **TRANSPARENT_BIN** | OSG 对透明物体**关闭深度写入**，深度缓冲失效 |
| `GL_LIGHTING` | **OFF** | 平面色，无立体感 |

**根因**：`GL_BLEND ON + alpha 0.85 + TRANSPARENT_BIN` → 深度写入被关 → 外表面不遮挡内表面 → 能看到内部。内表面法线朝里，光照下大脑误判朝向（空心面具错觉）。

### 绕序问题（CW vs CCW）

- STL 模型绕序为 **CW-out**（顺时针朝外）
- OSG 默认 CCW 为正面，CULL_FACE ON 时把外表面当背面剔掉
- 用其它软件查看确认：只看到背面（内表面）

## 最终方案

### 模型渲染

| 设置 | 值 | 说明 |
|------|-----|------|
| `GL_BLEND` | **OFF** | 不透明 |
| alpha | **1.0** | 完全不透明 |
| `RenderingHint` | **OPAQUE_BIN** | 深度写入正常 |
| `GL_DEPTH_TEST` | **ON（显式）** | 外表面遮挡内表面 |
| `GL_CULL_FACE` | **OFF** | 靠深度缓冲遮挡，不靠剔除 |
| `GL_LIGHTING` | **ON** | 有立体感 |
| 法线 | **叉积重算 + p1/p2 交换** | 法线朝外，光照正确 |
| `twoSided` | **true** | 双面都有光 |
| 模型文件 | **JEAMMSCAN.stl**（原始完整模型） | 清理版后续替换 |

### 标定/扫描视图切换

**标定时**（`onCalibDeviceClicked`）：
- 加载扫描仪 STL + 锁定相机
- 显示标定板 + 左右彩条（`calibLrBar`）+ 前后彩条（`calibFbBar`）
- 每次进入都 `show()`（修复第二次不显示问题）

**扫描时**（`onScanClicked` + 工具栏 5 个扫描按钮）：
- 隐藏标定板 + 左右彩条 + 前后彩条（`hide()`）
- 清空 3D 场景，恢复浅灰背景（0.878）
- 恢复中心十字、解锁相机、显示工具条

### 彩条控件管理

| 控件 | objectName | 位置 | 标定显示 | 扫描隐藏 |
|------|-----------|------|---------|---------|
| 左右容器 | `calibLrBar` | view3DArea 的 QVBoxLayout 顶部 | `show()` | `hide()` |
| 前后容器 | `calibFbBar` | viewContainer 的 QHBoxLayout 末尾 | `show()` | `hide()` |

> 前后容器从 `QVBoxLayout`（Layout 无法 hide）改为 `QWidget` 容器包裹 `QVBoxLayout`，才能 `hide()`。

### 工具栏扫描按钮信号连接

```
items[0] = 标点扫描  → connect → 隐藏标定元素 + 恢复默认视图
items[1] = 标定      → connect → onCalibDeviceClicked
items[2] = 面片扫描  → connect → 隐藏标定元素 + 恢复默认视图
items[3] = 点云扫描  → connect → 隐藏标定元素 + 恢复默认视图
items[4] = 双扫描    → connect → 隐藏标定元素 + 恢复默认视图
items[5] = 切片扫描  → connect → 隐藏标定元素 + 恢复默认视图
```

## 关键经验

1. **TRANSPARENT_BIN 会关深度写入**：这是 OSG 对透明物体的默认行为，导致深度缓冲失效。标定场景必须用 `OPAQUE_BIN`。
2. **STL 绕序可能反转**：CW-out 绕序在 OSG 中会导致 CULL_FACE 剔错面。用其它软件交叉验证。
3. **Layout 无法 hide**：QLayout 不是 QWidget，不能 `hide()`。需要用 QWidget 容器包裹 Layout，再 `hide()` 容器。
4. **控件只创建一次、反复 show/hide**：用 `if (!m_calibBoard2D)` 只在首次创建，之后每次 `show()` 即可。但要注意所有关联控件（彩条）都要 show。
5. **objectName 便于查找**：用 `findChild<QWidget*>("calibLrBar")` 可在任意层级查找控件，无需保存指针。

## 涉及文件

| 文件 | 改动 |
|------|------|
| `app/CalibDisplay.cpp` | 绕序交换 p1/p2；CULL_FACE OFF + DEPTH_TEST ON；twoSided true；alpha 1.0 |
| `app/MainWindow.cpp` | 扫描按钮信号连接；标定/扫描切换 show/hide；ArrowSlider 水平支持；彩条 objectName |
| `app/CalibDisplay.h` | 无变化 |

# 悬浮工具栏定位修复开发记录

## 问题

标定模式隐藏悬浮工具栏后，切换到扫描模式时工具栏虽然 `show()` 了，但位置在 3D 视图（左半边）的中间，而不是整个显示窗口的中间。

## 根因

`repositionFloatingToolbar()` 基于 `m_3dView->geometry()` 定位：

```cpp
QRect viewGeo = m_3dView->geometry();
QPoint viewBottomCenter = m_3dView->mapToGlobal(QPoint(viewGeo.width() / 2, viewGeo.height()));
```

标定时布局是 `[3D视图 | 标定板]`，`m_3dView` 只占左半边，所以工具栏居中在左半边。

## 修复

改为基于 `m_3dViewArea`（整个显示窗口区域）定位：

```cpp
QRect areaGeo = m_3dViewArea->geometry();
QPoint areaBottomCenter = m_3dViewArea->mapToGlobal(QPoint(areaGeo.width() / 2, areaGeo.height()));
```

`m_3dViewArea` 是包含 3D 视图 + 远近滑动条 + 标定板 + 彩条的整个区域，工具栏现在在整个显示窗口底部居中。

同时清理了重复的 `isVisible()` 检查。

## 涉及文件

| 文件 | 改动 |
|------|------|
| `app/MainWindow.cpp` | `repositionFloatingToolbar()`：定位基准从 `m_3dView` 改为 `m_3dViewArea` |

# 标定算子集成开发记录

## 背景

标定算子库（`modules/09_operatorlib/calibration/`）有 16 个完整实现的算子，但系统调用层（`app/stubs/`）全是空桩：
- `CameraCalibWorkflow::run()` 返回 `"Stub: camera calibration not implemented"`
- `LaserCalibWorkflow::run()` 同样是空桩

算子"已就位"但"未集成"。

## 需求

把标定算子集成到系统中，写独立的标定函数，**采集部分暂不写**（图像由调用方作为参数传入）。

## 算子接口分析

标定涉及的算子及其 `Execute` 接口：

| 算子 | 头文件 | Execute 输入 | Execute 输出 |
|------|--------|-------------|-------------|
| `IntrinsicCalibCPU` | `intrinsic_calib_cpu.h` | 左右角点 | 内参矩阵 + 畸变系数 + RMS |
| `ExtrinsicCalibCpu` | `extrinsic_calib_cpu.h` | 角点 + 内参 | R, T, E, F + 重投影误差 |
| `StereoRectifyCpu` | `stereo_rectify_cpu.h` | 内参 + R, T | R1, R2, P1, P2, Q + 有效区域 |

## 实现方案

### 文件结构

```
app/calib_workflow.h   — 接口定义
app/calib_workflow.cpp — 实现（调用真实算子）
```

### 标定流程

```
调用方采集图像 → runCameraCalibration()
  ├── 1. 角点检测（cv::findChessboardCorners + cornerSubPix）
  ├── 2. 内参标定（IntrinsicCalibCPU::Execute）
  │      → cameraMatrixL/R, distCoeffsL/R, RMS
  ├── 3. 外参标定（ExtrinsicCalibCpu::Execute）
  │      → R, T, E, F, stereoReprojError
  └── 4. 立体矫正（StereoRectifyCpu::Execute）
         → R1, R2, P1, P2, Q, validRoi
```

### 函数列表

| 函数 | 说明 | 算子调用 |
|------|------|---------|
| `runCameraCalibration()` | 完整流程（4 步） | 全部 3 个算子 |
| `runIntrinsicCalibration()` | 仅内参 | IntrinsicCalibCPU |
| `runExtrinsicCalibration()` | 仅外参 | ExtrinsicCalibCpu |
| `runStereoRectify()` | 仅矫正 | StereoRectifyCpu |
| `saveCalibResult()` | JSON 保存 | — |
| `loadCalibResult()` | JSON 加载 | — |

### 关键设计

1. **采集分离**：角点检测在采集阶段完成，标定函数只接收角点
2. **固定标定板参数**：`CHESSBOARD_COLS=6, CHESSBOARD_ROWS=7, CALIB_FRAME_COUNT=25`
3. **进度回调**：每个阶段通过 `std::function<void(int, const std::string&)>` 报告进度
4. **move-only 结果**：算子的 Result 结构体是 move-only（spec §3.3），调用方直接接收 move 结果
5. **JSON 序列化**：`cv::Mat` 转为 rows/cols/data 数组存入 JSON，可完整恢复
6. **激光标定依赖相机结果**：`LaserCalibInput` 持有 `CameraCalibResult*`，共享内外参

## 流程重构（第二版）

### 问题

第一版把角点检测放在标定函数内部（接收原始图像），但实际流程中：
- 角点检测应该在**采集阶段**做（实时显示检测结果、丢弃无效帧）
- 标定函数只接收**已验证的角点**

### 修改

| 项目 | 第一版 | 第二版 |
|------|--------|--------|
| `CameraCalibInput` | `leftImages/rightImages`（原始图像） | `leftCorners/rightCorners`（角点） |
| 角点检测 | 标定函数内部 | 采集阶段（UI层） |
| 标定板参数 | 可变参数 | 固定常量 `6×7, 25帧` |
| 单独函数 | 6 个（完整+内参+外参+矫正+存+读） | 4 个（完整相机+激光+存+读） |
| 激光标定 | 无 | `LaserCalibInput` 持有 `CameraCalibResult*` |

### 最终流程

```
采集阶段（UI层）
├── 打开左右相机
├── 采集25帧 → 实时检测棋盘格角点 → 显示反馈
├── 检测成功 → 保存角点；失败 → 丢弃

└── 输出：leftCorners[], rightCorners[], leftLaserImage, rightLaserImage

标定阶段（calib_workflow）
├── runCameraCalibration(corners)
│   ├── IntrinsicCalibCPU::Execute()  → 内参+畸变+RMS

    ├── EndpointExtract

        ↓
```
