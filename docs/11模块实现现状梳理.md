## 逐模块详情

### 模块1 · 标定 ✅ 可用

**已有代码**:
- `app/calib_workflow.cpp/h` — 标定工作流（相机标定4步 + 激光标定 + JSON保存/加载）
- `app/CalibDialog.cpp/h` — 标定UI对话框
- `app/CalibDisplay.cpp/h` — 标定3D显示（扫描仪模型 + 标定板 + 姿态偏差彩条）
- `framework/workflow/CalibrationWorkflow.cpp/h` — 工作流框架
- `framework/data/CalibStore.cpp/h` — 标定数据存储
- `modules/09_operatorlib/calibration/` — 32 cpp + 7 cu（内参/外参/矫正/温度补偿/激光平面映射等16算子）

**能跑的**: 相机标定(内外参+矫正) + 激光标定 + JSON落盘 + 标定UI

**缺失**: 姿态引导采集并行流水线、温度补偿完整流程、optical_flow_fuse依赖的PrevFrameState

## 关键观察

### 1. 代码分布与模块目录严重不匹配

```
模块目录(modules/)    实际代码位置
─────────────────    ──────────────
01_calibration (空)  → app/calib_workflow + framework/workflow
02_scanning (空)     → framework/workflow
03_rendering (空)    → app/OSGWidget
04_postprocessing(空)→ framework/workflow
05_file_io (空)      → app/file_io
06_device_control    → ✅ 代码在此（命名不符定义，应为"设备管理"）
07_ui_main (空)      → app/MainWindow（不应作为独立模块）
08_license (空)      → 应合并到"设备管理"
09_operatorlib       → ✅ 代码在此
10_edit (空)         → 编辑功能在 app/OSGWidget（应改名为"可观测性"）
11_marker (空)       → 不应作为独立模块（应改名为"安装部署"）
```

**9 个模块目录是空的**（仅占位），实际代码堆在 `app/`（单体应用）和 `framework/`（分层框架）里。

### 2. 模块目录命名与定义不符

当前目录命名 vs 正确定名:

| 当前 | 应为 |
|------|------|
| 05_file_io | 05_editing（编辑） |
| 06_device_control | 06_fileio（文件管理） — 代码在此但命名/编号错 |
| 07_ui_main | 07_session（会话管理） |
| 08_license | 08_devicemgmt（设备管理） — 合并license |
| 10_edit | 10_observability（可观测性） |
| 11_marker | 11_deploy（安装部署） |

### 3. 架构分层已有雏形

`framework/` 下已有分层骨架:
- **Data层**: PointCloudBuffer / CalibStore / FrameBuffer / DeviceStateCache
- **Workflow层**: CalibrationWorkflow / ScanWorkflow / PostProcessWorkflow / Pipeline
- **Service层**: SessionService / StateMachine / FaultHandler / ParameterManager
- **HAL层**: IMCU / IScannerCamera（接口定义）
- **Infra层**: EventBus / GpuRuntime / Scheduler / Watchdog（桩）

骨架在，但大部分是空壳——需要填实现。

### 4. 已能跑的最小闭环

标定→扫描(单帧)→渲染→导入导出 的最小链路可以跑通。缺的是:
- 扫描的**并行流水线**（P0）
- 扫描**启停控制**（P0）
- **PLY导出**接入扫描结果（P0）
- **后处理**流水线（P1）
